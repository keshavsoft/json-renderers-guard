Why GUARD exists

The problem is scattered knowledge about the same evolving input object, not a lack of tiny utility functions.

The problem

Different repositories validate different parts of the same component request. Examples and rules can drift when copied manually. When the input story changes, maintainers must discover every copy and update each one.

The role of GUARD

GUARD keeps named contracts, validation logic, examples, and tests in one package. Consumers call the appropriate contract rather than maintaining a second version of its rules.

What it does not own

It does not build table specifications, orchestrate rendering, or create DOM elements. Those remain the responsibilities of the existing packages.
