How to Use json-renderers-guard

Learn how to install, import, and validate JSON renderer inputs with full, modular, and fine-grained patterns.

1. Installation

Install via your package manager of choice:

npm install json-renderers-guard

2. Standard End-to-End Validation (guardFunc)

The default export guardFunc validates both the data specification keys (type, data, columns) and the mount configuration keys (targetHtmlId): 

import guardFunc from "json-renderers-guard";

const config = {
  type: "table",
  targetHtmlId: "customer-table-container",
  data: [
    { id: 1, customer: "Acme Corp", revenue: 54000 },
    { id: 2, customer: "Globex Ltd", revenue: 78000 }
  ],
  columns: [
    { columnName: "customer", width: "200px" },
    { columnName: "revenue", width: "120px" }
  ],
  appendPosition: "replace",
  showLog: false
};

try {
  // Directly pass config or wrap in { inConfig: config }
  guardFunc(config);
  console.log("Configuration is valid! Proceeding to render.");
} catch (error) {
  console.error("Validation failed:", error.message);
}
Return Value: When valid, guardFunc returns true. If any rule is violated, it throws an immediate descriptive TypeError or Error.

3. Headless Specification Validation (guardSpec)

In environments where no DOM target exists—such as Node.js batch scripts, server-side data preparation, or worker threads—use guardSpec(): 

import { guardSpec } from "json-renderers-guard";

const specConfig = {
  type: "table",
  data: [{ sku: "X100", stock: 45 }],
  columns: [{ columnName: "sku" }, { columnName: "stock" }]
};

// Validates type, data array, column definitions, and logs.
// targetHtmlId is NOT required here!
guardSpec(specConfig);

4. Mount-Only Validation (guardMount)

If your application has already validated the data model and only needs to verify the DOM container target and presentation options before attaching to the document: 

import { guardMount } from "json-renderers-guard";

guardMount({
  targetHtmlId: "dashboard-widget-4",
  appendPosition: "replace",
  classToApply: "table-striped custom-theme"
});

5. Granular Autonomous Field Validators

For micro-validations inside custom pipelines, each field validator is exported individually:

Validator Function Required Keys / Rules Enforced
validateType(config) Requires type string. Must not be empty.
validateTargetHtmlId(config) Requires targetHtmlId non-empty string.
validateData(config) Requires data to be a valid Array.
validateColumns(config) Requires columns to be an Array where each item has columnName.
validateShowLog(config) Optional. If provided, must be a boolean (true or false).

6. Using the NPX CLI

You can also run GUARD directly in your terminal or in CI/CD pipelines without importing it: 

# Output canonical config template
npx json-renderers-guard

# Output detailed JSON spec schema
npx json-renderers-guard --spec

# Validate any local configuration JSON file
npx json-renderers-guard validate ./my-table.json
