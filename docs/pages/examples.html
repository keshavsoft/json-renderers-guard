Practical Examples & Recipes

Explore ready-to-use recipes for common validation patterns, modular usage, and handling invalid input payloads.

Example 1: Full Valid Table Configuration

A complete, production-ready input object for table generation and rendering:

import guardFunc from "json-renderers-guard";

const tableConfig = {
  type: "table",
  targetHtmlId: "analytics-grid-mount",
  data: [
    { id: 101, product: "Widget A", sales: 1200, inStock: true },
    { id: 102, product: "Widget B", sales: 850, inStock: false },
    { id: 103, product: "Widget C", sales: 2400, inStock: true }
  ],
  columns: [
    { columnName: "product", width: "180px" },
    { columnName: "sales", width: "120px" },
    { columnName: "inStock" }
  ],
  appendPosition: "replace",
  classToApply: "table table-hover table-bordered",
  showLog: false
};

// Validates successfully and returns true
const isValid = guardFunc(tableConfig);
console.log("Validation result:", isValid); // Output: true

Example 2: Headless Data & Columns Validation (guardSpec)

Use this pattern on backend servers, CLI tools, or build scripts where you generate the AST specification without needing any DOM container ID: 

import { guardSpec } from "json-renderers-guard";

const reportSpec = {
  type: "table",
  data: [
    { country: "India", code: "IN", population: "1.4B" },
    { country: "United States", code: "US", population: "330M" }
  ],
  columns: [
    { columnName: "country" },
    { columnName: "code" },
    { columnName: "population" }
  ],
  showLog: false
};

// Succeeds! No targetHtmlId is expected or required.
guardSpec(reportSpec);
console.log("Spec data contract verified.");

Example 3: Mount Target Validation (guardMount)

Verify container targets, replacement options, and styling rules prior to mounting:

import { guardMount } from "json-renderers-guard";

const mountConfig = {
  targetHtmlId: "main-content-area",
  appendPosition: "replace",
  classToApply: "custom-responsive-table"
};

guardMount(mountConfig);
console.log("Mount target configuration is valid.");

Example 4: Catching and Handling Validation Errors

GUARD provides strict, descriptive errors when a contract rule is violated:

import guardFunc from "json-renderers-guard";

// Case A: Missing targetHtmlId
try {
  guardFunc({
    type: "table",
    data: [{ item: "Pen" }],
    columns: [{ columnName: "item" }]
    // targetHtmlId is missing!
  });
} catch (err) {
  console.error(err.message); 
  // "targetHtmlId is required and must be a non-empty string"
}

// Case B: Columns missing required columnName property
try {
  guardFunc({
    type: "table",
    targetHtmlId: "root",
    data: [{ item: "Pen" }],
    columns: [{ width: "100px" }] // columnName is missing!
  });
} catch (err) {
  console.error(err.message);
  // "Each column object must have a 'columnName' string property"
}

// Case C: Data is not an array
try {
  guardFunc({
    type: "table",
    targetHtmlId: "root",
    data: "invalid data payload", // Must be array
    columns: [{ columnName: "item" }]
  });
} catch (err) {
  console.error(err.message);
  // "data must be an array"
}
