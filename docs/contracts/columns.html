The column contract

A column object has a required identity and optional table presentation choices; it is not an unrestricted object.

Column fields

FieldStatusMeaning
columnNameRequiredNames the data key represented by the column. V1 rejects a missing, non-string, or blank value.
widthOptionalTable-specific sizing information. It guides column sizing, including the table's column-group/column width behavior. It is not a general-purpose field for every component type.
templateOptional in V1A broader table description that can shape more than a column group: header, body rows, cells, and footer. It is not required by the current contract, but it may become mandatory when the table template model is formalized.

Why columnName is different

Without columnName, the builder cannot reliably connect a declared column to the data field it represents. Width and template describe presentation; they do not identify the data field.

Why template deserves its own story

A template is not merely a display property for one column. It can coordinate the structure of multiple table regions. Its future requirements should be documented and tested as a table-level contract, rather than silently made mandatory by the guard before the builder is ready.

V1 rule: require columnName; allow width and template to be absent. Do not introduce new validation for optional fields until their accepted shape is agreed.
