json-renderers-guard

Universal, declarative input contracts and schema validation for JSON-driven specification builders. Decouples instruction dispatch from component semantics — zero DOM dependencies, pure data transformation.

📖 The Story: Why This Exists

The Monolithic Problem

In early declarative architectures, specification builders (such as json-renderers-build-table) were monolithic. The logic that iterated over columns, stamped table headers, computed cells, and mounted elements to the DOM was tightly fused with the instruction execution mechanism.

When validation rules and input examples were copied between different repositories, they began to drift. One package might enforce that a column must have a string columnName, while another might silently ignore missing columns, causing unexpected runtime crashes deep inside DOM mutation loops.

The Architectural Solution

json-renderers-guard provides one versioned, centralized contract authority to validate input objects before any downstream specification builder or DOM renderer processes them:

  • Pure Data Transformation: Zero DOM dependency. Runs seamlessly in Node.js, CLI scripts, Web Workers, or browsers.
  • Fail-Fast Boundary: Rejects invalid types, missing keys, or empty target IDs upfront with clear, actionable errors.
  • Decoupled Pipeline: Builders focus solely on AST generation, renderers focus on DOM mounting, and GUARD enforces contract integrity.

🧩 The Four-Repository Pipeline

GUARD sits beside the existing renderer packages as a shared boundary perimeter, not as a replacement:

Repository Responsibility Environment
json-renderers-guard Validates input contracts, schema rules, and field requirements. Pure Data (Node / Browser)
json-renderers-build-table Table-specific specification building (AST generation). Pure Data
json-renderers-build Component specification building for multiple UI primitives. Pure Data
json-renderers Orchestrates lifecycle, manages container mounting, and CSS classes. DOM Mount
json-to-tag Translates JSON element specifications into native DOM elements. DOM Native

🚀 Installation & Usage

Install via npm:

npm install json-renderers-guard

Standard End-to-End Validation (guardFunc)

Validates both the specification keys (type, data, columns) and the mount configuration keys (targetHtmlId):

import guardFunc from "json-renderers-guard";

const tableConfig = {
  type: "table",
  targetHtmlId: "users-table-container",
  data: [
    { id: 1, name: "Keshav", role: "Architect" },
    { id: 2, name: "Nalam", role: "Engineer" }
  ],
  columns: [
    { columnName: "name", width: "150px" },
    { columnName: "role", width: "120px" }
  ],
  appendPosition: "replace",
  showLog: false
};

// Returns true if valid; throws descriptive TypeError/Error if invalid
guardFunc(tableConfig);
Direct & Wrapped Config: guardFunc accepts the configuration object directly (guardFunc(config)) or wrapped in an input object (guardFunc({ inConfig: config })).

⚡ Dual-Phase Modular Guards

Modern applications often build specifications in headless environments (e.g., server-side rendering or build pipelines) where no DOM element exists yet. GUARD provides dedicated sub-guards for each phase:

1. Headless Specification Guard (guardSpec)

Validates data and columns without requiring a targetHtmlId:

import { guardSpec } from "json-renderers-guard";

guardSpec({
  type: "table",
  data: [{ id: 101, title: "Quarterly Report" }],
  columns: [{ columnName: "title" }]
});

2. Mount Guard (guardMount)

Validates container target and mounting options prior to DOM attachment:

import { guardMount } from "json-renderers-guard";

guardMount({
  targetHtmlId: "app-root",
  appendPosition: "replace",
  classToApply: "table table-striped"
});

📋 The Column Contract: Required vs Optional Fields

A column definition is not a free-form universe; it has strict boundary contracts:

Field Status Purpose
columnName Required Identifies the data key represented by the column. Missing or non-string values are rejected.
width Optional Table-specific sizing guideline. Guides column-group/column sizing behavior.
template Optional in V1 Broader table-level description that can coordinate multiple regions (header, rows, cells, footer).

🛠️ NPX Command Line Interface

GUARD includes a built-in CLI for scaffolding starter templates and validating JSON files without writing code:

# Output canonical config template to stdout
npx json-renderers-guard

# Generate a fresh config.json file
npx json-renderers-guard > config.json

# Validate any local JSON configuration file
npx json-renderers-guard validate ./my-table.json

# Output complete JSON schema specification
npx json-renderers-guard --spec
